# PR 설명 형식

## 우리 팀에서 새는 상황

PR 설명이 "수정함" 한 줄이어서 리뷰어가 의도와 검증 방법을 코드에서 역추적합니다.

## 규칙

PR 본문은 아래 세 부분을 모두 포함합니다.

1. 무엇과 왜: 변경 내용과 이유를 두세 문장으로
2. 검증: 실행한 명령과 결과 (예: `cd backend && uv run pytest`, 통과 수)
3. 위험과 되돌리는 방법: 영향 범위, 롤백 방법

수용 기준이 있는 변경은 해당 `requirements/` 문서와 기준 번호를 링크합니다.
