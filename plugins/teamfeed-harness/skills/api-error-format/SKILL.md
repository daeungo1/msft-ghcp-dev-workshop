# API 오류 응답 형식

## 우리 팀에서 새는 상황

엔드포인트마다 `{"detail": ...}`, `{"message": ...}`, 문자열이 섞여 나가서 프론트엔드가 오류마다 따로 처리합니다.

## 규칙

* 모든 오류 본문은 `{"error": {"code": "<대문자_스네이크>", "message": "<사람이 읽는 설명>"}}` 입니다.
* 상태 코드는 인증 없음 401, 권한 없음 403, 없음 404, 중복 409, 입력 오류 422를 씁니다.
* `HTTPException`을 직접 던지지 않고 앱의 공용 오류 모듈을 씁니다.
* 오류 메시지에 SQL, 파일 경로, 스택 트레이스를 넣지 않습니다.

## 예시

| 에이전트가 하려는 일 | 기대 동작 |
|---|---|
| `raise HTTPException(404, "not found")` | 공용 오류 예외로 바꿔 `{"error": {"code": "NOT_FOUND", ...}}`를 반환 |
| 응답에 `str(exc)`를 그대로 담음 | 일반화된 메시지로 대체 |

## 완료 확인

새 오류 경로마다 상태 코드와 본문 형식을 확인하는 테스트를 추가합니다.
