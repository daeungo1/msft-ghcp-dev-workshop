## 전체 흐름 (5시간 과정 중 세션 3)

핸즈온 180분(S0~S5 165분 + 회고 15분)에 휴식 15분을 더해 총 195분입니다.

| 경과 (분, 휴식 포함) | 단계 | 강사 시연 포인트 | 체크포인트 안내 시점 |
|---|---|---|---|
| 0 ~ 25 | S0 Spec | 같은 요청 두 번 → 구조 차이, spec-kit 초기화 | 18분 |
| 25 ~ 55 | S1 회원·게시글 | 테스트를 고쳐서 통과시키는 장면, test-writer → implementer 순서 | 21분 |
| 55 ~ 85 | S2 팔로우 | 훅이 경계 위반을 차단하는 장면 (CLI) | 21분 |
| 85 ~ 100 | 휴식 | | |
| 100 ~ 115 | S3 피드 | 추측 컬럼 오류 → MCP `describe_table` | 10분 |
| 115 ~ 150 | S4 신고 | 테스트 통과 + 인가 누락 → 리뷰어가 Critical 보고 | 25분 |
| 150 ~ 180 | S5 패키징 | sandbox 저장소에 플러그인 설치 | 21분 |
| 180 ~ 195 | 회고·자가진단 | 정답 회고표 공개 | |

## 늦은 참가자 기준

단계 시간의 70%가 지나면 `scripts/checkpoint.sh S<n-1>`로 직전 정답에서 합류하도록 안내합니다.

## 핵심 메시지

* 인스트럭션과 스킬은 부탁(확률적 안내), 훅·테스트·CI·리뷰 게이트는 강제(결정적 통제)
* 가끔 새는 것을 항상 막는다
* 하네스는 우리 팀 BP의 첫 번째 버전이고, 다음 버전은 고객 저장소에서 만든다

## 강사 참고: final 브랜치

질문 대응이나 데모가 필요하면 `final` 브랜치(태그 `v1.0`)를 보여 줍니다. 회고표·자가진단 예시, 내 팀 규칙 2~3개, marketplace 등록까지 끝난 플러그인, 모든 하네스가 켜진 PR 이력을 담은 "다 끝나면 이렇게 된다" 기준본입니다.
