## 단계별 시연 스크립트

각 시연은 3분 안에 끝냅니다. 참가자 실습 전에 보여 주면 "무엇이 새는가"를 먼저 보게 됩니다.

### S0

1. 빈 세션에서 "회원과 글을 다루는 백엔드를 만들어줘"를 두 번 실행합니다.
2. 두 결과의 디렉터리 구조와 네이밍 차이를 나란히 보여 줍니다.
3. `specify init --here --force --integration copilot` 후 `/speckit-constitution`을 실행해 원칙이 생기는 과정을 보여 줍니다.

### S1

1. 하네스 없이 "회원 가입 API 만들어줘"를 요청합니다. 구현만 나오고 테스트가 없거나 뒤에 붙는 것을 확인합니다.
2. 실패하는 테스트를 일부러 만들고 에이전트가 테스트를 고치는지 구현을 고치는지 지켜봅니다.
3. `tdd` 스킬과 test-writer, implementer를 켜고 같은 요청을 다시 합니다.

### S2

1. 하네스 없이 팔로우 서비스가 `members` 패키지의 내부 모듈을 직접 import하는 코드를 만들게 합니다.
2. 훅을 켠 뒤 같은 요청을 합니다. preToolUse가 거부하거나 postToolUse가 경계 위반을 알리는 것을 보여 줍니다.
3. 훅은 CLI에서 동작합니다. VS Code의 훅 지원은 프리뷰입니다.

### S3

1. MCP 없이 피드 쿼리를 요청합니다. `posts.content`처럼 존재하지 않는 컬럼을 쓰면 실제 컬럼은 `body`라는 것을 보여 줍니다.
2. `sqlite-ro` MCP를 켜고 `describe_table`로 스키마를 읽게 합니다. 쓰기 쿼리는 거부되는 것도 보여 줍니다.

### S4

1. 신고 목록 API를 구현하게 하고 테스트가 모두 통과하는 것을 확인합니다.
2. `security-reviewer`로 리뷰하면 `GET /api/reports`에 관리자 검사가 없다는 Critical이 나옵니다.
3. 구현자와 리뷰어가 다른 맥락에서 일하는 것이 포인트입니다.

### S5

1. 빈 `sandbox` 저장소에서 `/skills list`가 비어 있음을 보여 줍니다.
2. `copilot plugin install ./plugins/teamfeed-harness` 후 같은 명령에 `tdd`가 나타나는 것을 보여 줍니다.
3. `final`의 `.github/plugin/marketplace.json`으로 marketplace 등록 흐름을 설명합니다.

## 늦은 참가자 기준

단계 시간의 70%가 지나면 `scripts/checkpoint.sh S<n-1>`로 직전 정답에서 합류하도록 안내합니다.
자세한 기준은 같은 스크립트가 출력하는 안내를 따릅니다.

## 핵심 메시지

* 인스트럭션과 스킬은 부탁(확률적 안내), 훅, 테스트, CI, 리뷰 게이트는 강제(결정적 통제)입니다.
* 가끔 새는 것을 항상 막는 것이 하네스입니다.
* 하네스는 우리 팀 BP의 첫 번째 버전이고, 다음 버전은 고객 저장소에서 만듭니다.

## 강사 참고: final 브랜치

질문 대응이나 데모가 필요하면 `final` 브랜치(태그 `v1.0`)를 보여 줍니다. 회고표 예시, 내 팀 규칙 2~3개, marketplace 등록까지 끝난 플러그인을 담은 "다 끝나면 이렇게 된다" 기준본입니다.
참가자에게는 회고 시간 이후에 공개합니다.
