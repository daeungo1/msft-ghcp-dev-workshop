참가자의 회고표는 정답이 있는 표가 아닙니다. 아래는 각 함정에서 흔히 예상되는 관찰입니다. 리허설 결과(`facilitator/trap-log.md`)로 갱신하세요.

| 단계 | 함정 | 하네스 없이 일어나기 쉬운 일 | 붙인 하네스 | 통제 방식 | 붙인 뒤 기대하는 변화 |
|---|---|---|---|---|---|
| S0 | 문장에 따라 구조와 스타일이 달라짐 | 같은 요청에 패키지 구조와 에러 형식이 매번 다름 | constitution, 인스트럭션, AGENTS.md | 안내 | 같은 요청에 같은 구조가 나옴. 긴 세션에서는 가끔 어김 |
| S1 | 테스트 없이 완료 보고 | 구현만 쓰고 "완료"라고 보고하거나 테스트를 나중에 맞춰 씀 | `tdd` 스킬, 역할 분리 에이전트 | 안내 + 역할 분리 | 테스트 커밋이 앞서고 실행 증거가 보고에 포함됨 |
| S2 | 다른 패키지 코드를 직접 import | 서비스가 다른 패키지의 repository를 직접 호출 | import-linter, 훅, CI | 강제 | 위반이 편집 직후 알려지고 CI에서도 막힘 |
| S3 | 스키마를 추측한 쿼리 | 존재하지 않는 컬럼으로 쿼리를 작성 | 읽기 전용 SQLite MCP | 도구 범위 제한 | 스키마를 읽고 쿼리를 작성, 쓰기 시도는 거부됨 |
| S4 | 관리자 인가 누락 | 테스트는 통과하지만 일반 회원이 신고 목록을 조회 가능 | 읽기 전용 리뷰어, rubber duck, CodeQL | 독립 리뷰 | 리뷰어가 Critical로 보고, 403 테스트 추가 |
| S5 | 하네스가 저장소에 갇힘 | 새 저장소에서 스킬과 에이전트가 사라짐 | 팀 플러그인 | 배포·재사용 | 한 줄 설치로 다른 저장소에서 동일하게 동작 |

## 안내와 강제를 나누는 기준

* 안내(S0, S1)는 대부분 지켜지지만 가끔 샌다. 어겨도 리뷰에서 잡히는 것에 씁니다.
* 강제(S2, S3, S4)는 항상 막는다. 한 번 새면 비용이 큰 것에 씁니다.
