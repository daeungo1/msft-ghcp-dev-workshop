# TeamFeed Constitution

TeamFeed를 만드는 모든 사람과 에이전트가 따르는 원칙입니다. 각 원칙에는 지켰는지 확인하는 방법이 붙어 있습니다.

## 1. 테스트가 먼저다

* 기능은 실패하는 테스트를 먼저 커밋하고 그다음에 구현합니다.
* 통과하지 않는 테스트는 구현을 고쳐서 통과시킵니다. 테스트를 약하게 만들지 않습니다.
* 검증: `git log`에서 테스트 커밋이 구현 커밋보다 앞서 있고 `cd backend && uv run pytest`가 통과합니다.

## 2. 패키지 경계를 지킨다

* 도메인 패키지는 `members`, `posts`, `follows`, `feed`, `reports`입니다.
* 다른 패키지의 기능은 그 패키지의 `api` 모듈로만 호출합니다. `models`, `repository`, `service`를 직접 import하지 않습니다.
* 검증: `cd backend && uv run lint-imports`가 통과합니다.

## 3. 작은 변경만 한다

* 요청받은 범위만 수정하고 관련 없는 파일은 건드리지 않습니다.
* 가정이 있으면 구현 전에 먼저 말합니다.
* 검증: 변경 파일 목록이 요청 범위와 일치합니다.

## 4. 에러 응답 형식을 통일한다

* 모든 오류는 `{"error": {"code": "...", "message": "..."}}` 형식으로 응답합니다.
* 상태 코드는 인증 없음 401, 권한 없음 403, 없음 404, 중복 409, 입력 오류 422를 씁니다.
* 검증: 오류 경로마다 상태 코드와 본문 형식을 확인하는 테스트가 있습니다.

## 5. 보안 기본값을 지킨다

* 관리자 기능은 서버에서 역할을 검사합니다. 화면에서 숨기는 것만으로는 충분하지 않습니다.
* 사용자 입력은 항상 길이와 형식을 검증하고 SQL에는 바인딩 파라미터만 씁니다.
* 비밀과 개인 정보는 로그와 응답에 남기지 않습니다.
* 검증: 권한 없는 호출이 403을 받는 테스트가 있고, 원시 문자열로 조립한 SQL이 없습니다.
