description: 진단 5개 축으로 우리 팀에서 가장 자주 새는 곳과 그 자리에 둘 강제 하나를 고르는 카드
---

기준은 두 가지입니다. 한 번 새면 비용이 큰 곳에는 강제(훅, CI, 리뷰 게이트)를, 어겨도 리뷰에서 잡히는 곳에는 안내(인스트럭션, 스킬)를 둡니다.

| 축 | 질문 | 우리 팀에서 가장 자주 새는 곳 | 그 자리에 둘 강제 1개 |
|---|---|---|---|
| 요구·명세 | 에이전트가 무엇을 만들지 어디서 읽나? 요구가 모호할 때 누가 멈추나? | | |
| 설계·경계 | 모듈 경계와 의존 방향을 누가 검사하나? | | |
| 테스트·검증 | 완료의 증거는 무엇이고 누가 확인하나? | | |
| 보안·리뷰 | 작성자와 다른 눈이 인가, 입력, 비밀을 보나? | | |
| 배포·운영 | 되돌릴 수 없는 명령이나 변경을 누가 막나? | | |

## 작성 예시

| 축 | 우리 팀에서 가장 자주 새는 곳 | 그 자리에 둘 강제 1개 |
|---|---|---|
| 설계·경계 | 서비스 간 DB 테이블 직접 참조 | import-linter 계약 + CI 게이트 |
