# TDD 절차

이 파일은 스타터입니다. TODO를 지우고 우리 팀 방식으로 채우세요.

## 원칙

* TODO 테스트와 구현의 순서에 대한 원칙을 한 줄로 적습니다
* TODO 테스트를 고치고 싶어질 때의 규칙을 한 줄로 적습니다

## 절차

1. TODO 먼저 하는 일 (힌트: 수용 기준을 테스트 이름으로 옮김)
2. TODO 실패를 확인하는 방법 (힌트: 실행 명령과 기대하는 실패 모양)
3. TODO 최소 구현
4. TODO 전체 테스트와 정리

## 금지

* TODO 하면 안 되는 것 (힌트: 테스트를 약하게 만들어 통과시키기)

## 완료 보고 형식

* TODO 완료를 보고할 때 반드시 첨부할 증거 (힌트: 실행한 명령과 결과 요약)
